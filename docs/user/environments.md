# Окружения, библиотеки и свои Docker-образы

Обычный пользователь работает через общий JupyterHub. Отдельный JupyterHub для каждого пользователя не нужен: это усложняет доступ, порты, токены, безопасность и сопровождение.

## Когда достаточно обычного окружения

Используйте готовое окружение, если вам нужны стандартные библиотеки для Python, R, анализа данных или ноутбуков.

Доступные варианты:

- `Python SciPy Notebook`
- `Data Science Notebook`
- `R Notebook`
- `PyTorch CPU Notebook`
- `CUDA 13 Lab (GPU)`

## Когда нужен новый Docker-образ

Новый образ нужен, если:

- требуются конкретные версии Python, R, CUDA или системных библиотек;
- нужно воспроизводимое окружение для статьи, диссертации или гранта;
- нужно установить тяжелые зависимости один раз, а не ставить их вручную каждый запуск;
- готовый проект уже поставляется с `Dockerfile`;
- стандартные окружения не запускают ваш код.

Если нужен один небольшой Python-пакет, сначала уточните у ответственного: возможно, проще добавить его в существующий образ.

## Как запросить новый образ

Напишите ответственному:

1. Название проекта.
2. Нужна ли GPU.
3. Язык и версию: Python, R, Julia и т.д.
4. Список библиотек и версий.
5. `requirements.txt`, `environment.yml` или `Dockerfile`, если они есть.
6. Команду проверки, по которой понятно, что окружение работает.

Пример заявки:

```text
Проект: microscopy-segmentation
Нужна GPU: да
Python: 3.12
Библиотеки: torch, torchvision, opencv-python, scikit-image, pandas, matplotlib
Проверка: import torch; print(torch.cuda.is_available())
```

После сборки администратор добавит образ в список JupyterHub. Пользователь сможет выбрать его при запуске сервера.

## Можно ли запустить отдельный JupyterLab-контейнер

Можно, но это особый сценарий. Его запускает администратор.

Отдельный контейнер нужен, если проекту требуется:

- долгоживущий JupyterLab на отдельном порту;
- нестандартная конфигурация;
- отдельный сервис рядом с Jupyter;
- проверка готового Docker-образа;
- отдельные лимиты CPU/RAM/GPU.

Перед запуском отдельного контейнера нужно согласовать:

1. Название проекта и владельца.
2. Docker-образ или `Dockerfile`.
3. Нужна ли GPU.
4. Сколько CPU и RAM можно выделить.
5. Какие папки подключить.
6. Нужно ли открывать порт.
7. Кто будет иметь ссылку и токен доступа.

Для обычной научной работы предпочтительнее свой образ внутри общего JupyterHub.
