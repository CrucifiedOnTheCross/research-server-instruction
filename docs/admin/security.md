# Безопасность

Эта страница фиксирует правила, которые помогают не потерять данные и не дать пользователям лишние права.

## Пароли и токены

- Не храните реальные пароли в публичной wiki.
- Не вставляйте токены облачных хранилищ в общие ноутбуки.
- Для примеров используйте заглушки вроде `CHANGE_ME_LONG_RANDOM_TOKEN`.
- Перед публикацией изменений проверяйте репозиторий на случайные секреты.

Пример проверки:

```bash
rg -n "password|пароль|token|secret|ключ|wsdjki|aO1Map|95f5" .
```

## Docker-доступ

Не добавляйте обычных пользователей в группу `docker`.

Причина: доступ к Docker почти равен root-доступу к серверу. Пользователь с Docker-доступом может подключить системные каталоги, изменить файлы хоста или обойти ограничения.

Обычная модель:

- пользователи работают через JupyterHub;
- новые библиотеки добавляются через Docker-образы;
- отдельные контейнеры запускает администратор;
- Portainer доступен администраторам.

## Данные

Правила:

- личные рабочие файлы - в `/home/jovyan/work`;
- проектные данные - в `/srv/projects/<project-name>`;
- исходные датасеты - в `/srv/datasets/<dataset-name>`;
- закрытые проекты - только через отдельные группы и права;
- чувствительные данные не кладутся в общие папки без согласования.

## Права на проектные папки

Для закрытых проектов:

1. Создайте отдельную группу.
2. Добавьте в нее только участников проекта.
3. Назначьте группу владельцем папки проекта.
4. Проверьте, что другие пользователи не имеют доступа.
5. Подключайте эту папку только нужным окружениям.

## Перед запуском внешнего Docker-образа

Проверьте:

1. Кто автор образа.
2. Есть ли `Dockerfile` или документация.
3. Какие volumes он требует.
4. Какие порты открывает.
5. Нужны ли привилегированные режимы.
6. Не содержит ли образ подозрительных entrypoint-скриптов.

Не запускайте неизвестные образы с `--privileged` без необходимости.
